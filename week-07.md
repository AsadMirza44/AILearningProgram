# Week 7: Capstone Development and AI Showcase

## Week Goal

Help learners combine prompting, data thinking, RAG, MCP, **Week 6 agent building blocks**, and responsible AI into one practical capstone they can present clearly.

## Concepts Explorer Topics

### Problem Statement and User Persona
Every capstone starts with a real user need and a clearly defined audience.

### AI Workflow
The workflow should show inputs, prompts, data or knowledge, tools, outputs, and review points.

### Plugins in a Capstone
Explain when an installable extension pack is needed instead of scattered prompts.

### Rules in a Capstone
Always-on guidance for standards, safety, citation, and review habits.

### Skills in a Capstone
Repeatable workflows such as testing, demo rehearsal, or release checks.

### Subagents in a Capstone
Delegated focused work with clear handoffs between agents.

### Tools and MCP in a Capstone
Callable actions plus Week 5 MCP where structured tool access helps.

### Hooks in a Capstone
Event-driven guardrails before or after tool use, saves, or sessions.

### RAG in a Capstone
Trusted knowledge retrieval, citations, and source quality.

### MCP in a Capstone
Structured tools, resources, and prompts when the capstone needs external access.

### Model Choice, Frontier vs Open-Source, and Parameters
Justify hosted, local, or hybrid model choices.

### Cost, Inference, and Deployment Tradeoffs
Token usage, hardware, privacy, and recurring cost.

### Agents, MoE, and System Scale
Architecture and workflow choices at larger scale.

### Safety, Ethics, and Testing
Privacy, review, bias checks, failure handling, and limits.

### Presentation and Reflection
Clear demo, diagram, prompts, and lessons learned.

## Agent Building Blocks Table (from Week 6, applied to capstone)

| Building Block | Capstone Question | Key Difference |
| --- | --- | --- |
| Plugins | Does your project need an installable extension pack? | Product-level extension bundles |
| Rules | What always-on guidance should your assistant follow? | Passive guidance; does not execute actions |
| Skills | Which repeatable workflow should your agent reuse? | On-demand expertise packs |
| Subagents | Should work be split across focused agents? | Independent workers with separate context |
| Tools | What actions must your system perform? | Active capabilities during a turn |
| Hooks | What guardrails should run on events? | Reactive automation tied to events |

## Core Ideas

- start from the problem, not the tool
- justify every Week 6 agent layer you include
- RAG and MCP from Week 5 still matter in the capstone
- model choice is a tradeoff, not a popularity contest
- safe systems need testing and human review

## Class Activities

### Activity 1: Capstone Agent Building Blocks Mapping
Teams apply the Week 6 comparison table to their capstone and justify each layer used.

### Activity 2: Capstone Planning Workshop
Define user, problem, prompts, RAG, MCP, agent layers, and outputs.

### Activity 3: Subagent Task Split for Capstone Teams
Split work across roles with clear handoffs and review points.

### Activity 4: Tool Permission and Hook Guardrail Design
List allowed tools, forbidden tools, and at least one hook or review checkpoint.

### Activity 5: Model Choice Pitch
Explain frontier vs open-source or hybrid model choice.

### Activity 6: Risk Review Circuit
Rotate peer review for privacy, retrieval, tool use, agent-layer confusion, and cost.

### Activity 7: Demo Flow Rehearsal
Practice a two-minute capstone explanation with safety and agent-layer notes.

### Activity 8: Final Showcase
Present the project and answer questions about design choices.
